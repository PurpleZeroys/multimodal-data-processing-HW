# multimodal-data-processing-HW

Репозиторий содержит два ноутбука с решением домашнего задания по модулю "Внимание".

## Структура

| Файл | Содержимое |
|---|---|
| dz1-attention.ipynb | Шаг 1: реализация split_heads, merge_heads, scaled_dot_product_attention, TransformerBlock.forward. Все 17 проверок зелёные. |
| dz1-bughunt.ipynb | Шаг 2: вариант seed 42, найдены и исправлены 3 ошибки (таблица ответов внутри ноутбука), обучение исправленной модели, кривая потерь и пример генерации. |

## Среда выполнения

- Google Colab (https://colab.research.google.com)
- Runrime: CPU (задание не требует GPU; на T4 работает быстрее)
- PyTorch 2.14.1 (в Colab предустановлен, дополнительная установка не нужна)

## Как воспроизвести

1. Откройте ноутбук в Colab: **Файл -> Открыть ноутбук -> GitHub/загрузка**.
2. **Runtime (Среда выполнения) -> Run all (Запустить все)**.
3. Ожидаемый результат:
   - dz1-attention.ipynb: пройдено 17 из 17, "Все проверки зелёные".
   - dz1-bughunt.ipynb: тоже 17/17 + обучение: потери падают с ~3.18 до ~0.04 за 600 шагов, генерация воспроизводит обучающий шаблон

## Фиксация случайности (seed)

- **seed 42** в заголовке dz1-bughunt.ipynb - это идентификатор варианта задания, а не генератор случайных чисел
- **Обучение** (dz1-bughunt.ipynb, ячейка "Обучение исправленной модели"): первой строкой стоит torch.manual_seed(0) - фиксирует инициализацию модели и выбор батчей. Благодаря этому кривая потерь воспроизводится от запуска к запуску.
- **Проверки**: каждая проверка внутри себя вызывает torch.manual_seed(N) N от нуля до семи, перед созданием тестовых данных, поэтому результаты проверок не зависят от порядка запуска.
- **Генерация** (dz1-bughunt.ipynb, последняя ячейка) сэмплирует токены (temperature=0.8, top_k=10), поэтому текст может отличаться от запуска к запуску - это ожидаемо. Структура текста (слова, пробелы, пунктуация) сохраняется.

## Найденные ошибки (вариант seed 42)

1. sinusoidal_positional_encoding: отсчёт позиций с 1 вместо 0 → заменено на torch.arange(length).
2. LayerNorm.forward:  среднее и дисперсия по батчу (dim=0) вместо признаков (dim=-1).
3. scaled_dot_product_attention: softmax по оси запросов (dim=-2) вместо оси ключей (dim=-1).
